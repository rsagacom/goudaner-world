## 三、维度一：代码与工程质量（A / 92）

### 3.1 架构：合同分层是这个项目最大的工程资产

```
chat-core（纯合同，1,060 行）
   ↑            chat-storage（快照+append-only journal）
   │            crypto-mls（ring 原语 + webpush RFC 合同）
   ├──────── transport-waku（transport 抽象，feature-gated）
   │
Gateway（30,574 行，唯一真源：auth/room/policy/moderation）
   ├── H5 Web Shell（主入口，68 个模块）
   ├── TUI（13,591 行）/ CLI（5,277 行）/ HTTP Agent 通道
```

- **合同下沉模式已被验证两次**：`attachment://` 引用解析从 Gateway 下沉 chat-core（Gateway/TUI 零漂移）；WebPush 加密放 crypto-mls（Gateway 只消费）。合同层无 IO、可穷举单测，是"多端一致"的成本最低解。
- **依赖面极瘦**：Gateway 直接依赖 16 项；本轮 WebPush 全链路（RFC 8291+8292）**零新第三方依赖**（ring+ureq 树内已有）——"先审计再引依赖"的门禁产生了实际收益。
- **crate 划分合理**：chat-core 纯数据合同、chat-storage 唯一持久化层、crypto-mls 唯一密码学层——三层边界在 R2 与 WebPush 两轮开发中都被证明没有泄漏。

### 3.2 测试与门禁：防止"感觉写完了"的体系已经成型

- 完整 release gate（fmt / clippy -D warnings / workspace tests / panic scan / 脚本合同单测 / shell 直连 smoke / 真实双浏览器 smoke / provider federation / **WebPush e2e 冒烟**）多次退出码 0。
- 门禁体系在本轮**三次真实拦截**：panic 扫描拦下 3 处历史 `.expect`；realness 抓获灯箱遮罩挡热点 hover（干净 HEAD 对照定位）；备份在档校验单测用 PATH 注入验证 fail-closed。门禁不是摆设的证据充分。
- WebPush 的验证深度值得保留为范式：RFC 官方向量逐字节复现 → 浏览器 WebCrypto 解密回环（互操作）→ 集成断言（帧头/VAPID 头）→ 生产公网合同。

### 3.3 代码健康度：R4 上帝对象在好转，但有明确的下一步

- app.js：峰值 9,342 行 → **7,623 行**，累计拆出 68 个子模块；本轮新增模块（compress/lightbox/install-hint/push-client/fallback）全部走"决策纯函数 + DOM 工厂 + fake-dom 单测"范式，不再往 app.js 堆。
- admin-ds.js 3,155 行未动（R6 双后台体系的一部分），是下一个最胖目标；蓝图既定结论"不做机械搬运"仍然有效。
- Rust 侧网关 30,574 行按 runtime 分文件清晰；`message_runtime.rs` 与 `http_write_routes.rs` 是两个持续膨胀点（分别为消息合同与 60+ HTTP handler 落点），若继续增长建议按域拆 handler 模块。

### 3.4 技术债登记（更新版）

| 编号 | 债务 | 状态 |
|---|---|---|
| R1 | 全局粗锁（读路径无快照化） | 后置（>5 并发信号触发）；R2 已把写成本常数化，锁压力只剩读侧 |
| R2 | 全量重写 IO | ✅ **本轮清偿**（journal + 双预算压实 + 压测量化） |

## 六、维度四：安全与隐私（B+ / 85）

**做得对的**：
- OTP 登录（生产禁 dev bypass，readiness 断言）；会话哈希存储、登出即吊销；
- 附件能力 URL（128bit CSPRNG）+ 无扩展名（CF 不缓存，隐私边界实测确认）；
- 推送内容端到端加密（RFC 8291），推送服务只见密文；订阅密钥非法即 fail-closed；
- 登出静默退订防跨居民泄漏；邮件认证链（SPF/DKIM/DMARC p=quarantine）完整并复核；
- 备份含敏感文件的在档 fail-closed 校验；密钥类 0600 + Debug 脱敏。

**如实登记的边界**：
- 传输层 TLS 由 CF 终结，Gateway 本身仍明文 HTTP（仅 loopback）——单机部署可接受，多机即升级项；
- `crypto-mls` 名义上是 MLS，实际是骨架——**私聊并非 E2EE**，服务器可读。这条必须继续在所有对外物料中如实声明（当前已做到）；
- admin token / session token 哈希存储 ✓，但 gateway.env 内含多个明文 secret（root-only 0600，符合单机威胁模型）。

## 九、结论与下一阶段排序

**复盘总结论**：09-04 复盘"工程强/运营弱"的判断在 30 小时高强度开发后依然成立，且工程侧被进一步夯实（R2 清偿、WebPush 全链路、生产切换、合同面三层覆盖）。项目的**瓶颈完成转移：从"能不能做出来"彻底转为"有没有人用"**。

**下一阶段排序（严格优先级）**：
1. **§5 真人验收收尾**（进行中）——双居民 + 推送真机项，剩余最后一块自动化无法替代的拼图；

4. **阶段②小圈子内测**（微信群种子池，邀请码已就绪）——首轮 5–10 人，反馈驱动功能排序（群聊/多设备/富媒体按痛感插队）；

**明确不做（维持）**：通用 IM 市场竞争、去中心化叙事拉新、无用户信号的功能堆叠。
